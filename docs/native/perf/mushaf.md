## ما تبيّن
- **الخطوط مضمَّنة في الحزمة (`Data/mushaf/fonts/p{n}.ttf`) وليست مُنزَّلة**: لا زمن تنزيل ولا استئناف؛ بند «تنزيل على دفعات» غير منطبق على البنية الحالية (156MB داخل الحزمة).
- مسار البيانات سريع أصلًا؛ العنق الحقيقي في طبقة العرض: `MushafPageView.init` يقرأ الخط والصفحة **على الخيط الرئيسي** عند كل إعادة تقييم لـ`body` القارئ، و`TabView` يحمل 604 ابنًا.
- سلاسة التقليب (إطارات ضائعة) تُقاس على المحاكي/الجهاز بـInstruments؛ لم تُقَس هنا (لا يُدّعى رقمها).

## بعد #3201 (LRU للصفحات/التخطيط + تحميل مسبق ±2 في الخلفية)
القياس: `MushafPerfTests.testAfterCache` (سطر `MUSHAF_PERF_AFTER`)؛ تقليب كل 120ms مع prefetch، مرّتان (الضجيج بين التشغيلين ظاهر).

| فتح بارد | 42.5 ms | 57.8 / 49.1 ms (ضمن الضجيج؛ لم يتغيّر المسار البارد) |
| فتح دافئ | 2.0 ms | 0.02 / 0.04 ms (كاش) |
| تقليب 50 صفحة: متوسط | 5.7 ms | 1.3 / 3.3 ms |

- الذاكرة لا تنمو مع التقليب: الحد 24 صفحة، والهبوط عن القيمة الأولية بسبب تحرير بيانات الفهرس/الصفحات المؤقتة وقت القياس.

- **الإطارات الضائعة الفعلية لم تُقَس** (تحتاج Instruments على المحاكي/الجهاز) فلا أدّعي رقمها؛ وبالتالي لا مسوّغ قياسيًّا لاستبدال `TabView` الآن، ويبقى كما هو.

## فتح الشاشة والبحث (ن3، 2026-10-15)
- **السبب الجذري:** `MushafScreen` كان يبني `MushafSearch` (114 ملف JSON + تطبيع) متزامنًا على الخيط الرئيسي داخل `.task` (macOS debug: 4358 ms)، ويبحث بمسح خطي لكل استعلام (حتى 615 ms).
- **الإصلاح:** فهرس بايتات مسبق الحساب (`memmem` + بحث ثنائي) يُبنى متوازيًا وخارج الخيط الرئيسي؛ تُعرض الصفحة فور جاهزية المستودع والفهرس، ويلتحق البحث لاحقًا.
- القياس (`MushafPerfTests.testSearchBaseline`، macOS debug): بناء 4358 → 166 ms؛ الاستعلامات 0.2–2.3 ms (كانت حتى 615)؛ استعلام بلا نتيجة 482 → 1.9 ms؛ النتائج مطابقة للمسح الخطي (تسعة استعلامات).
- **المحاكي (n3-sim، iOS 26.5، `MUSHAF_PERF` في السجل، فئة `mushaf-perf`):** `screen_task_start` ← `repo_index_ready` +0.37 s ← `search_ready` +1.2 s بعدها. الصفحة تُرسم قبل جاهزية البحث. افتتاح التطبيق نفسه (IntroPolicy) ≈1.6 s، فالوصول للمصحف ≈2.5 s من الإطلاق (الهدف < 3 s).
- رقم 23 s في `MushafFlipHitchUITests` ليس زمن التطبيق: هو `app.launch()` (انتظار خمول XCUITest) ولم يتغيّر بعد إصلاح البحث؛ فلا يُعتمد.
- **التقطيع:** `swipeRight` في XCUITest يقيس زمن حقن اللمسة لا زمن الإطار، ولم ينتج xcresult مقياس `XCTHitchMetric`؛ فلا رقم صالحًا بعد ولا ادعاء.
