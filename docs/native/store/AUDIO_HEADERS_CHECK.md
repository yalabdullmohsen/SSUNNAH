# AUDIO_HEADERS_CHECK — فحص ترويسات طلبات الصوت على RC3

> إلى ن4. يثبت أن اتصالات التلاوة بـ**EveryAyah** و**MP3Quran** لا تحمل غير الترويسات القياسية، ليطابق الواقعُ فقرةَ مضيفي الصوت في `PRIVACY_CHECK.md` (القسم 1). **لم يُنفَّذ أي فحص بعد**؛ كل بند «لم يُتحقق» حتى يصل بناء RC3 ويُعلَّم ✔ بدليل. لا يُعدَّل كود Swift ضمن هذه الوثيقة.

## الإعداد
1. بناء RC3 مُثبَّت على جهاز حقيقي (iPhone)، وجلسة Proxy على الحاسوب (Charles أو mitmproxy أو Proxyman) على الشبكة نفسها، مع تثبيت شهادة الـProxy على الجهاز للقراءة داخل TLS. (الشهادة للفحص فقط ولا تُحفظ في المستودع.)
2. اختبر **مرتين**: (أ) وأنت **مسجّل الدخول** بحساب تجريبي، (ب) **بلا حساب**؛ لأن الخطر الوحيد هو تسرّب جلسة الحساب إلى المضيفين.
3. نظّف سجل الـProxy قبل كل سيناريو.

## السيناريوهات
| # | السيناريو | المتوقع في الشبكة | ✔/✘ + دليل |
|---|---|---|---|
| 1 | فتح التطبيق وتصفح المصحف وأقسام أخرى **دون** تشغيل صوت | صفر طلبات إلى `everyayah.com` و`mp3quran.net` وما يتبعهما | |
| 2 | تشغيل آية/سورة (بث) | الطلبات تذهب إلى المضيف المطلوب فقط، وبعد الضغط على التشغيل لا قبله | |
| 3 | تنزيل سورة للاستماع دون اتصال | الطلبات إلى المضيف المطلوب فقط، وبعد طلب التنزيل صراحةً | |
| 4 | تغيير القارئ ثم التشغيل | مضيف القارئ الجديد فقط؛ لا طلبات احتياطية صامتة لمضيف آخر | |
| 5 | إعادة التشغيل من الكاش بعد التنزيل (وضع الطيران) | صفر طلبات شبكة | |
| 6 | التطبيق في الخلفية والصوت يعمل | لا طلبات جديدة غير ما يلزم تدفق التشغيل | |

## ما يُفحص في كل طلب (لكل مضيف على حدة)
| الترويسة/الحقل | المتوقع | ✔/✘ + دليل |
|---|---|---|
| `User-Agent` | القيمة القياسية لـCFNetwork/AVFoundation (اسم التطبيق وإصدار النظام) دون معرّف مستخدم أو بريد | |
| `Authorization` | **غائبة** | |
| `Cookie` / `Set-Cookie` المُرسَل من التطبيق | **غائبة** (لا ملف تعريف مرسَل) | |
| `apikey` أو ترويسات Supabase (`x-client-info`…) | **غائبة** | |
| أي ترويسة مخصصة تبدأ بـ`X-` | **غائبة** | |
| معرّف المستخدم أو البريد أو الاسم أو الموقع داخل المسار أو الاستعلام (`?`) | **غائبة**؛ المسار ملف صوتي فقط (سورة/آية/قارئ) | |
| `Referer` / `Origin` | غائبة أو لا تحمل بيانات | |
| نوع الطلب | `GET` (وربما `HEAD`/`Range` للبث) فقط، بلا جسم (body) | |
| بروتوكول الاتصال | HTTPS (لا HTTP نصي) | |

## دليل من الكود على 104/105 (ن4، 2026-10-16) — ليس بديلًا عن فحص الجهاز بالـProxy
- البث: `AVPlayerAudioEngine.swift:15` و`AccountCarModeScreen.swift:57` يستعملان `AVPlayerItem(url:)` بلا `AVURLAssetHTTPHeaderFieldsKey` ⇒ ترويسات AVFoundation القياسية فقط (لا Authorization ولا apikey).
- التنزيل: `OfflineRecitation.urlSessionFetch` يستعمل `URLSession.shared.data(from:)` بلا ترويسات مخصصة ولا جسم (GET).
- `setValue(…forHTTPHeaderField:)` (apikey/Authorization/Prefer) موجود في مسارات Supabase فقط (`RemoteTransport` و`AccountNetwork` و`AccountDeletion`)، ولا يلتقي بمسار الصوت.
- مضيفا الصوت مذكوران نصًا في `AccountTexts.swift:352-353` فقط؛ لا يوجد تجميع روابط يحمل مُعرِّفات المستخدم.
- يبقى لمالك الجهاز: السيناريوهات 1–6 بالـProxy (تثبيت شهادة الفحص على جهازه). حتى يُنفَّذ تبقى الخانات أعلاه «لم يُتحقق».

## نتيجة ن5 على build 106 (2026-10-17) — دليل كود، لا فحص Proxy
> البناء 106 (VALID على TestFlight). المصدر المفحوص: الإيداع `2536452` («تسجيل رفع 106»). **لا يُغني عن السيناريوهات 1–6 بالـProxy على جهاز حقيقي؛ لم أُجرِها (لا جهاز ولا تثبيت شهادة Proxy من جهتي).**

| البند | النتيجة على 106 | الدليل |
|---|---|---|
| البث | ✔ لا ترويسات مخصصة | `Platform/AVPlayerAudioEngine.swift:15` `AVPlayerItem(url:)` بلا `AVURLAssetHTTPHeaderFieldsKey`؛ وكذلك `AccountCarModeScreen.swift:57` |
| التنزيل | ✔ GET بلا ترويسات ولا جسم | `Audio/OfflineRecitation.swift:146` `URLSession.shared.data(from: url)` |
| Authorization / apikey | ✔ غائبة عن مسار الصوت | `setValue(…forHTTPHeaderField:)` في `RemoteTransport` و`AccountDeletion` و`AccountNetwork` وSupabaseAuthAdapter فقط؛ لا تلتقي بمضيفي الصوت |
| ترويسات/كوكيز مخصصة عامة | ✔ لا `httpAdditionalHeaders` ولا `HTTPCookieStorage` ولا `AVURLAsset` | بحث على كامل حزمة SunnahNative |
| معرّف مستخدم في المسار | ✔ لا | الروابط من جدول القرّاء (`SurahReciter.surahURL`) سورة/قارئ فقط |
| ما يبقى بلا دليل | ✘ لم يُتحقق | `Referer/Origin` وما تضيفه AVFoundation/CFNetwork فعليًا على السلك، والمضيف الاحتياطي الصامت، وHTTPS في الطلب الفعلي: يحتاج Proxy |

الخلاصة لقرار الإفصاح: الكود يدعم الحالة «لا معرّفات تتجاوز IP وUser-Agent القياسي»، لكن الحالة تبقى **غير مثبتة بالسلك** حتى تُملأ الخانات بلقطات Proxy من ن4/يوسف على 106.
