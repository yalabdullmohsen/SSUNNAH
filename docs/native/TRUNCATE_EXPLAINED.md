# ما هو «TRUNCATE عند يوسف» بالضبط

**ما هو:** تفريغ أربعة جداول سجلات قديمة في قاعدة الإنتاج (Supabase) لخفض حجمها من ~570MB إلى ما دون حد الخطة المجانية 500MB.

| | |
|---|---|
| الجداول | `public.akp_structured_logs`، `public.automation_step_logs`، `public.akp_source_health`، `public.akp_metrics_snapshots` (سجلات/قياسات نظام أتمتة المحتوى القديم، أقدم من 30 يومًا) |
| لماذا | فوق 500MB قد تتحول القاعدة إلى **قراءة فقط**: يفشل التسجيل وحذف الحساب (مطلب App Review 5.1.1(v)) والمزامنة |
| أثر عدم التنفيذ | لا أثر على TestFlight الداخلي الحالي ولا على القراءة. **خطر على الإرسال للمراجعة**: إن دخلت القاعدة القراءة فقط فسيفشل حذف الحساب أمام المراجع |
| يمس بيانات حقيقية؟ | لا. لا محتوى ولا بيانات مستخدمين ولا `auth.*` ولا الحسابات (reviewer لا يُمس). التطبيق لا يقرأ هذه الجداول (فُحص: صفر مراجع في ios-native وSunnahNative) |
| التراجع | لا تراجع للبيانات المفرَّغة (سجلات تشغيل فقط). لذلك الخطوة 1ب تتحقق أولًا من غياب مفاتيح أجنبية |

## القرار (ن4)
**لازم قبل الإرسال للمراجعة، وليس قبل TestFlight الداخلي.** ما سجّلتُه: بند «شرط المالك» في RELEASE.md. التنفيذ بيد يوسف لأنه إنتاج؛ لم أنفّذ شيئًا.

## الخطوات (لصق في Supabase → SQL Editor، على مرحلتين)
1. الصق **الخطوتين 1 و1ب** من `docs/native/backend/cleanup-legacy-logs.sql` (قراءة فقط). شرط المتابعة: استعلام المفاتيح الأجنبية يعيد **صفر صفوف**. دوّن `db_size` قبل.
2. الصق الخطوة 2 وحدها:
   ```sql
   TRUNCATE TABLE public.akp_structured_logs, public.automation_step_logs, public.akp_source_health, public.akp_metrics_snapshots;
   ```
   (بلا CASCADE عمدًا: إن وُجد مفتاح أجنبي يفشل الأمر ولا يمس شيئًا آخر.)
3. أعد استعلام الحجم: المطلوب `db_size` < 500MB بهامش. إن بقي قرب 500MB فالجداول التالية مرشّحة وتحتاج قرارك قبل أي حذف: `mke_decisions`، `mke_quality_reports`، `akp_review_queue`، `content_engine_publish_audit`.
