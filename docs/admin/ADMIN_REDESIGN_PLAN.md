# Admin Redesign Plan

## أهداف التجربة

حديث · تحريري · موجّه بسير العمل · مناسب للجوال · AA · بلا لوحة CRUD صاخبة.

## موجات

| موجة | نطاق | حالة |
|---|---|---|
| **1** | Unicode · تدقيق تخطيط · تنقّل 7 وجهات · وثائق | **هذه الموجة** |
| 2 | مساحة المراجعات (Inbox) | لاحق |
| 3 | مساحة المحتوى الموحّدة | لاحق |
| 4 | مركز التصنيف (شجرة) | لاحق |
| 5 | التحليلات (اتجاهات) | لاحق |
| 6 | صقل نهائي · كثافة · أزرار · FAB · safe-area | لاحق |

## ما يُحفظ دائمًا

- الصلاحيات وRLS  
- منطق الأعمال والمراجعة والنشر  
- سجل التدقيق (واجهة محلية + سياسات خادم)  
- مسارات Legacy حتى اكتمال الترحيل لكل مركز

## ما لا يُحفظ

- هيكل التنقّل المتشظي (~40 قسمًا في الشريط)  
- بطاقات عملاقة فارغة  
- نصوص `\uXXXX` الحرفية  
- مصطلحات داخلية (slug/seed) في واجهة المحرر — تُرحَّل لتشخيص المطوّر لاحقًا

## مخاطر

| خطر | تخفيف |
|---|---|
| كسر روابط محفوظة | aliases + Redirect |
| اتساع نطاق موجة 1 | تجميد موجات 2–6 |
| تراجع Unicode | بوابة `admin-unicode-jsx-gate` |

## Rollback

إعادة `nav.ts` / `catalog.ts` / مسارات AppRoutes من commit قبل الموجة؛ الإبقاء على فكّ Unicode في المصادر آمن.
