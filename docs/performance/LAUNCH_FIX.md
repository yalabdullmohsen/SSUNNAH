# LAUNCH_FIX — دخولية واحدة بلا تكرار ولا وميض

**النطاق:** مسار الفتح من لمس الأيقونة حتى أول شاشة حقيقية (iOS يحمّل الموقع الحي `https://www.ssunnah.com`).
**المنهجية:** بناء إنتاج محلي + Playwright (Chrome) 390×844، CPU ×4 + Fast 3G، نهاري/ليلي؛ سيناريوهات: فتح بارد، فتح بعد نشر، إعادة تحميل، خلفية→عودة (`visibilitychange`)، فتح بلا اتصال. وتحقق مباشر على الإنتاج قبل الإصلاح.

## جرد الدخوليات قبل الإصلاح

| # | الطبقة | المصدر | الملاحظة |
|---|---|---|---|
| 1 | LaunchScreen الأصلي | `ios/App/App/Base.lproj/LaunchScreen.storyboard` + `LaunchBackground.colorset` | لون فقط؛ **فاتح/داكن حسب الجهاز** بينما الويب نهاري افتراضيًا |
| 2 | Capacitor SplashScreen | `capacitor.config.ts` (`launchShowDuration: 0`) | لا يظهر فعليًا؛ يُخفى عند التسليح |
| 3 | دخولية HTML | `#mj-launch-splash` في `index.html` + `mj-launch-splash-boot.js` + `splash-screen.ts` | «سُنّة» + عبارة + شريط تقدّم فوق سطح LaunchScreen |
| 4 | صفحة خطأ التحميل الأصلية | `public/native-load-error.html` (`errorPath`) | **نفس شكل الدخولية** (اسم + عبارة + تقدّم) ثم إعادة محاولة تُظهر (3) مجددًا |
| 5 | إعادة التحميل عند الإقلاع | `public/boot-legacy-cache.js` + `purgeStaleRuntimeCaches({ reloadOnce: true })` | كل reload = دخولية (3) من جديد |

## الأسباب الجذرية

1. **الدخولية تتكرر (2–3 تحميلات للمستند):** الحزمة تحمل commit بـ7 أحرف (`vite.config.ts`) و`/version.json` بـ8. `boot-legacy-cache.js` يخزّن الثمانية، ثم `purgeStaleRuntimeCaches` يقارن حرفيًا فيرى «نسخة مختلفة» → مسح كاش + reload. على الإنتاج (مُقاس): **أول زيارة = مستندان، وبعد كل نشر = 3 مستندات** (reload من السكربت القديم ثم من الحزمة). ولأن المستند network-first (SW + `max-age=0`) فالحزمة الجارية هي الأحدث أصلًا — كل reload هدر خالص.
2. **دخول بطيء:** `boot-legacy-cache.js` سكربت خارجي **حاجب للمحلل في `<head>`** (رحلة شبكة قبل أول رسم) + سلسلة الـreload أعلاه + على iOS: `AppDelegate` **يمسح كاش WKWebView (قرص/ذاكرة/fetch) عند كل إقلاع** فكل فتح = تنزيل كامل للحزم من الصفر (ويسابق التحميل الأول فيرفع احتمال `native-load-error`).
3. **وميض في الليلي:** دورة متغيرات في `theme-aliases.css` (`--mj-bg: var(--surface-app)` و`--surface-app: var(--mj-bg)`) تُبطل الاثنين، فتصير خلفية `html/body` **شفافة** من وصول CSS الحزمة حتى طبقات الليل المؤجلة (≈0.4–1s)؛ داخل التطبيق يظهر خلفها لون WKWebView الفاتح.
4. **شاشات متشابهة الشكل:** LaunchScreen لوني ثم دخولية HTML بعلامة ونص ثم (عند التعثر) صفحة خطأ بنفس العلامة ثم الدخولية مرة أخرى.
5. **رسالة/قفزة عابرة أثناء الإقلاع:** شريط «أنت غير متصل…» يُعرض فور التركيب و`position: sticky` داخل التدفق فيزيح الصفحة (CLS ≈0.12–0.18 عند الفتح بلا اتصال).
6. **عدم تطابق اللون الأصلي:** LaunchScreen داكن في وضع الجهاز الليلي بينما خلفية WKWebView (`ios.backgroundColor`) والويب الافتراضي فاتحان → داكن→فاتح عند كل فتح لمستخدمي الوضع الليلي للجهاز.

## الإصلاح

**PR الويب (يُنشر فورًا):**
- حذف `public/boot-legacy-cache.js` ووسمه من `<head>` — لا طلب حاجب ولا reload عند تغيّر النسخة.
- `purgeStaleRuntimeCaches` بلا reload إطلاقًا، ومقارنة النسخة ببادئة (`isSameBuildVersion`: 7 مقابل 8 أحرف = نفس البناء).
- دخولية واحدة: `#mj-launch-splash` صار **سطحًا لونيًا فارغًا** = LaunchScreen الأصلي (لون فقط، نفس المكان، بلا شعار/عبارة/تقدّم) حتى أول شاشة حقيقية؛ تُزال مرة واحدة ولا تعود على Resume.
- كسر دورة `--surface-app`/`--mj-bg` في الليلي.
- شريط عدم الاتصال: لا يظهر أثناء الإقلاع (بعد استقرار الهيكل فقط)، وطبقة `fixed` فوق الشريط السفلي — لا إزاحة ولا تغطية للهيدر.
- حذف كود دخولية ميت: `MajlisSplash.tsx`، `hideAppSplash`/`armSplashAutoHide`، `SPLASH_TAGLINE`، `generate-splash.mjs`، `generate-silent-splash-assets.py`، `test-splash-timing.mjs` (كان يفترض 650–1200ms).

**PR الأصلي (يتطلب بناء متجر):**
- `AppDelegate`: مسح كاش WKWebView **مرة واحدة لكل بناء تطبيق** بدل كل إقلاع.
- `LaunchBackground` فاتح فقط (#F8F6F1) = خلفية WKWebView = الويب الافتراضي.
- `native-load-error.html`: حالة التحميل سطح لوني فقط (لا دخولية ثانية)؛ رسالة الخطأ وزر إعادة المحاولة بعد الفشل النهائي فقط.

**الفتح بلا اتصال:** الويب يعرض صفحة `offline.html` النهائية مع «إعادة المحاولة» (لا رسائل عابرة)؛ الدخول إلى التطبيق نفسه بلا اتصال يتطلب تخزين مستند الواجهة في SW، وهذا ممنوع عمدًا ببوابة `verify-deploy-cache-versioning.mjs` (منع مستند قديم) — قرار للمالك. داخل iOS لا يعمل SW للأصل البعيد (بلا App-Bound Domains) فالمسار هو `native-load-error.html` بحالته النهائية.

## المتبقي

- صفحات prerender (روابط عميقة): `post-build-seo.mjs` يفكّ `<noscript>` فيصير CSS الكامل (≈150KB) حاجبًا للرسم → أول رسم ≈5.9s على Fast 3G. إصلاحه يكشف `#seo-shell` بلا تنسيق تحت LHCI (الدخولية تُزال فورًا تحت webdriver) — يحتاج استراتيجية تنسيق لـ`#seo-shell` أولًا.
- زمن أول شاشة (≈8.5s تحت الخنق) يحكمه تنزيل/تنفيذ الحزمة الأولى؛ بعد إصلاح iOS يُخدم من كاش WKWebView في الفتحات اللاحقة.
- التحقق على جهاز iOS فعلي بعد بناء المتجر.
