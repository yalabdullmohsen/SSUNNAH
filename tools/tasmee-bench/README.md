# tasmee-bench — قياس وضع «تسميع» على Mac

يقيس الدقة والتأخير لمحرك التسميع (WhisperKit + مطابِق الكلمات) على تلاوات بحقيقة أرضية على مستوى الكلمة.

**الصوت لا يُودَع في المستودع ولا يُشحن في التطبيق.** المدوّنة تُبنى محليًا من مقاطع Quran.com
(`/api/v4/chapter_recitations/{id}/{chapter}?segments=true`) لأغراض القياس الداخلي فقط، وتبقى خارج git.

## الخطوات

1. **المدوّنة:** نزّل `ch67_<id>.mp3` و`ch67_<id>.json` لكل قارئ، حوّلها: `afconvert -f WAVE -d LEI16@16000 -c 1 in.mp3 out.wav`، ثم
   `python3 build_corpus.py <corpusDir> artifacts/majalis/public/data/quran-v2/pages` (ينتج `set/` بـ٨ تلاوات نظيفة + ٥ بضوضاء مُحاكاة).
2. **النموذج:** `tools/tasmee-model/convert.sh base <workDir>` (انظر `docs/tasmee/MODEL.md`).
3. **التشغيل:** `swift build -c release` ثم `run_all.sh <modelsDir> <corpus/set> <runsDir>`.
   فك الترميز بلا prompt مستقل عن المطابِق → `replay.ts` يعيد تشغيل المطابِق الإنتاجي (TypeScript) على السجلات؛
   أما prompt فيعتمد على مؤشر المطابِق فيُشغَّل متصلًا (مطابِق Swift المطابق منطقيًا).
4. **التقييم:** `score.py <runsDir> <corpus/set>`.

## ما يقيسه وما لا يقيسه
- التأخير = لحظة اكتمال الفك (ساعة الصوت + زمن الحساب الفعلي، بنمذجة طابور) ناقصًا **نهاية** نطق الكلمة الحقيقية.
- الحساب على Apple M1؛ **لا يمثّل iPhone** (ANE/ذاكرة/حرارة). البطارية والحرارة تُقاس على الجهاز عبر شاشة القياس المخفية في التطبيق.
- الضوضاء المحاكاة (ثرثرة/وردي/غرفة) ليست تسجيلات بيئية حقيقية، والقرّاء محترفون (أنظف من المستخدم العادي).
