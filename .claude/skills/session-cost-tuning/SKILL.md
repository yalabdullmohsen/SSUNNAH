# ضبط تكلفة الجلسة

المصدر: توصيات منشورة عن توفير توكنات Claude Code (مقالات المجتمع، لا وثائق رسمية). **تحقق من اسم كل متغير/أمر في وثائق Claude Code الحالية قبل اعتماده**، فقد تتغير.

## عادات
- بين مهمتين مختلفتين: `/rename` ثم `/clear` (والعودة بـ`/resume`)؛ ولا تُبقِ المهمة القديمة في سياق الجديدة.
- `/context` لمعرفة ما يملأ النافذة، و`/usage` لتتبع الاستهلاك قبل المهام الكبيرة.
- `/compact` مبكرًا مع تعليمات ما يبقى (الهدف، الملفات المعدّلة، الأخطاء الفاشلة، الخطوة التالية) وما يُحذف (الاستكشاف القديم، السجلات المكررة).
- سمِّ الملفات بدقة بدل «اقرأ المشروع»؛ وحدّد معيار التحقق (اسم الاختبار والنتيجة المتوقعة) من البداية.
- قاطع الوكيل مبكرًا إن بدأ يقرأ ما لا علاقة له.
- موديل أخف للمهام الروتينية، والأثقل للقرارات المعمارية؛ وجهد منخفض للتعديلات البسيطة.

## إعدادات (على مستوى المستخدم `~/.claude/settings.json` أو البيئة)
- `permissions.deny` للمسارات الضخمة/الحساسة: `.env`, `secrets/**`, `node_modules/**`, `dist/**`, `build/**`, `coverage/**`, `*.log`، وفي سُنّة أيضًا `test-results/**` و`graphify-out/**` ما لم تُطلب.
- حدّ مخرجات الطرفية والأدوات الخارجية (متغيرات مثل `BASH_MAX_OUTPUT_LENGTH` و`MAX_MCP_OUTPUT_TOKENS` حسب المنشور؛ تحقق من الاسم).
- عطّل خوادم MCP والإضافات غير المستخدمة؛ كل إضافة تضيف حملًا ثابتًا لكل جلسة.

## في المستودع
- `CLAUDE.md` قصير (قواعد حاكمة فقط)، والتفاصيل في `.claude/rules/*` أو مهارات تُستدعى عند الحاجة.
- وجّه سجلات الاختبار والبناء عبر `grep`/`tail` (مثال: `pnpm test 2>&1 | grep -A5 -E "FAIL|ERROR" | head -120`).
- ما سبق في `lean-context`؛ هذه المهارة للإعدادات والبيئة.
